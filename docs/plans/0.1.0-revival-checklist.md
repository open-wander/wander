# Wander 0.1.0 Revival Checklist

## Purpose

This is the authoritative checklist for the Wander 0.1.0 revival. Other plan
documents provide detail, but an item is not a release requirement unless it
is represented here or explicitly added here.

The release goal is a secure, single-binary Wander distribution that preserves
the approved Nomad 1.6-era operational contract while using Wander-owned code,
branding, and UI. New product features belong after 0.1.0 unless they are
needed to restore that approved contract.

## Status rules

- `[x]` means evidence exists in the repository or in a recorded test run.
- `[ ]` means incomplete, unverified, or awaiting an explicit scope decision.
- Comparing a feature is not the same as implementing or testing it.
- A UI feature is complete only when success, empty, unavailable, and denied
  states are handled without fabricated data.

## 1. Licensing and provenance boundary

- [x] Document the rule that later Nomad source must not be copied, merged, or
      used as an implementation source.
- [x] Confirm the current implementation source has no `BUSL-1.1` or Business
      Source License headers as of 2026-10-20. Documentation may mention those
      identifiers when recording the boundary.
- [ ] Establish the exact commit and file-level license manifest from which
      Wander may inherit source. Do not assume every file in a version tag has
      the same license.
- [x] Treat the local `v1.6.5` tag as a mixed-license behavioral baseline, not
      blanket source permission. The tag contains 45 files marked
      `BUSL-1.1` (37 in the old UI and 8 elsewhere); the exact paths in
      `docs/licenses/baseline-busl-exclusions.txt` are excluded from Wander
      implementation work.
- [x] Audit the rewritten UI and its commit history for retained paths, headers,
      and Git-detectable copies from those files. The evidence and limits are
      recorded in [Wander License Provenance Audit](license-provenance-audit.md).
- [ ] Obtain project-owner approval of the provenance audit. Remove and
      independently rewrite any unapproved derivation found by that review.
- [x] Record a license-safe parity method. Permitted behavior sources and
      clean-room restrictions are documented in
      [License-safe parity method](license-safe-parity-method.md).
- [x] Produce a source/dependency engineering inventory for the release
      artifacts, including browser asset hashes and retained notices. See
      `docs/licenses/README.md`.
- [x] Replace consul-template's compiled BUSL Vault Kubernetes authentication
      dependency with the source-identical MPL-2.0 release and enforce that
      resolution in CI.
- [x] Remove the compiled go-spin dependency whose archive omitted a complete
      license notice while preserving deployment-status progress feedback.
- [x] Include the Wander license and generated third-party notice/source bundle
      in release archives, OCI images, and native Linux packages. Archive CI
      rejects artifacts missing the required manual and browser notices.
- [x] Add a CI check that rejects prohibited source license markers.
- [x] Add a release review process for provenance that cannot be determined
      from license markers alone (`docs/licenses/release-review.md`).
- [ ] Complete and approve that review against the final 0.1.0 commit.

## 2. Compatibility scope and parity matrix

The project owner decided on 2026-10-24 that Wander 0.1.0 must preserve every
applicable Nomad 1.6.5 OSS capability. Missing behavior is release-blocking;
there are no implicit UI omissions. Functionality exclusive to a different
edition is not part of the OSS drop-in target, and any other intentional
difference requires explicit approval.

- [x] Create a route-by-route matrix containing the baseline capability,
      Wander route, API operations, mutations, ACL requirements, namespace and
      region behavior, UI states, and automated test evidence. Exact baseline
      paths awaiting approved black-box capture are explicitly marked in the
      [UI route parity matrix](ui-route-parity-matrix.md).
- [x] Classify every applicable Nomad 1.6.5 OSS baseline capability as
      `required for 0.1.0`. Edition-only functionality is `not applicable`;
      post-0.1 features are limited to capabilities absent from that baseline.
- [ ] Obtain explicit approval for every intentional 0.1.0 difference.
- [ ] Verify behavior for service, batch, system, sysbatch, periodic,
      parameterized, and dispatched jobs where the approved baseline supports
      them.
- [ ] Verify single-region/multi-region, single-namespace/multi-namespace,
      ACL-disabled, anonymous, client-token, management-token, empty-cluster,
      degraded-cluster, and API-error states.

### Earlier comparison coverage

The earlier 46-task comparison covered many visible templates and components,
but it was not a complete behavioral parity audit. It did not create a route,
action, ACL-state, and regression-test matrix. Its completed checkboxes mean
that comparisons were performed; they do not mean the recorded gaps were
implemented.

The direct route inventory also found baseline areas absent from that task
list: ACL roles and tokens, job clients, services, dispatch and variables,
client/server monitor pages, job templates, optimization views, nested CSI
plugin allocations, and task-scoped filesystem routes. Each remains subject to
the licensing gate above and must be classified before release.

## 3. UI shell and cross-cutting behavior

### Completed blocker: namespace and region isolation

- [x] Replace the process-global namespace selection and shared API-client
      mutation with request/browser-scoped namespace state. One user's
      selection must never change another user's reads or mutations.
- [x] Pass the request-scoped namespace and region through every applicable
      API client read, mutation, log stream, exec session, and filesystem
      request; remove inappropriate `default` hard-coding.
- [x] Preserve namespace and region selection across navigation and reloads
      with explicit selection URLs and HTTP-only, browser-scoped fallback
      cookies.
- [x] Validate inaccessible or unknown namespace and region selections before
      persisting them, including selection by a namespace-restricted ACL token.
- [x] Finish the link/HTMX URL-propagation audit. Direct scoped URLs now carry
      namespace and region through links, forms, HTMX, fetch, log streams, and
      exec WebSockets without modifying external or static-asset URLs.
- [x] Add a disposable-cluster test with at least two namespaces containing
      distinguishable jobs and resources.
- [x] Add a two-browser-session regression test proving namespace selections
      cannot leak between users, plus namespace-restricted ACL coverage.
- [x] Apply the same request-isolation audit and concurrent-session test to
      region selection.
- [x] Exercise region switching against a disposable, federated multi-region
      cluster. The embedded-browser harness now starts distinct `global` and
      `region-a` agents, federates them, registers distinguishable jobs, and
      verifies remote reads and scoped navigation through the primary server.

- [x] Embed the UI in the Wander binary and serve it at `/ui/`.
- [x] Redirect `/` to `/ui/` while retaining the query string.
- [x] Preserve `ui { enabled = false }` behavior.
- [x] Keep the global search below breadcrumbs at desktop widths.
- [x] Use a full-width footer with one visible version label.
- [x] Remove the unsupported Alpine focus-trap usage and its console warnings.
- [ ] Verify responsive navigation, breadcrumbs, search, dialogs, tables, and
      workspaces at phone, tablet, laptop, and wide desktop widths.
- [ ] Verify consistent loading, empty, forbidden, not-found, API-error, and
      disconnected states on every route.
- [x] Verify namespace and region selection on every applicable read and
      mutation; no request may silently fall back to the wrong scope. A fresh
      browser direct-URL test covers navigation, HTMX, fetch, and mutation
      endpoints without relying on selection cookies.
- [ ] Complete keyboard and screen-reader coverage for dialogs, menus, tabs,
      tables, editors, file trees, logs, and exec—not only primary navigation.
- [x] Classify the inherited global keyboard shortcuts through the approved
      Nomad 1.6.5 black-box comparison. The global shortcut panel and its
      applicable navigation/help behavior are required for 0.1.0.
- [x] Restore the applicable global keyboard shortcuts, help panel,
      enable/disable preference, and rebinding behavior.
- [x] Defer complete dark mode until after 0.1.0 and track it separately in
      [Wander UI Dark Mode](dark-mode.md).

## Explicitly post-0.1

The following do not block 0.1.0 unless their classification changes:

- complete system/light/dark theme support;
- support OpenBao as an alternative Vault-compatible secrets backend;
- migrate build and browser-test tooling to a pinned Node 24 LTS patch after
  the revival release; Node.js remains absent from the Wander runtime;
- new scheduler or orchestration behavior not present in the approved baseline;
- UI convenience features with no approved baseline equivalent; and
- protocol or storage changes that would weaken drop-in compatibility.
